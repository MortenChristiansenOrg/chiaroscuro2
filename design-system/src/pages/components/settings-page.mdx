# Settings Page

Built-in page for editing global browser settings. Opens as a tab via `settings:open` command. VS Code-inspired layout with category navigation, search filtering, and live auto-save.

## Anatomy

1. **Settings header** — title with gear icon + search input
2. **Category nav** — left sidebar with scroll-spy active indicator
3. **Settings content** — scrollable area with categorized setting items
4. **Setting item** — label, description, and inline control
5. **Provider editor** — CRUD list for search providers with inline editing

## States

### Loading
When settings haven't been received yet, centered "Loading settings..." text in `var(--muted-foreground)`.

### Empty Search
When search query matches no settings, centered message: "No settings match [query]".

### Default
Full settings UI visible with all categories expanded.

---

## Behavior

- **Auto-save**: Changes are saved optimistically to the store and debounced (300ms) before persisting to main process.
- **Singleton tab**: Only one settings tab can exist at a time. Re-opening activates the existing tab.
- **Search filtering**: Client-side filter on setting definitions. Hides non-matching categories entirely.
- **Scroll-spy**: IntersectionObserver on category sections updates active nav link.

## Accessibility

- All form inputs have associated labels via `aria-label`
- Remove buttons include `aria-label="Remove provider"`
- Category nav links use standard `<a>` elements
- Semantic heading hierarchy: `<h1>` for title, `<h2>` for categories
