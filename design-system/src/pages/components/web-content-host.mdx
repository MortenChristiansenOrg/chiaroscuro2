# Web Content Host

The content area where web pages render. An Electron `WebContentsView` occupies this region; the React side provides the container, reports its bounds, and shows an empty state when no tab is active.

## Anatomy

1. **Container** — rounded, inset panel with shadow; flex-grows to fill remaining space beside the sidebar.
2. **Web content** — native `WebContentsView` positioned by main process to match container bounds.
3. **Empty state** — centered hint text shown when no tab is active.

## States

| State | Visual |
|-------|--------|
| No active tab | Semi-transparent glass bg (`oklch(1 0 0 / 0.08)`), light hint text centered |
| Active tab | Opaque white bg (`--content-bg`), `WebContentsView` fills container |
| Loading | Loading state handled by address bar spinner; content host unchanged |

---

## Behavior

- **Bounds reporting.** A `ResizeObserver` + `window.resize` listener reports the container's `getBoundingClientRect()` to main process via `tabs:report-content-bounds`.
- **WebContentsView positioning.** Main process calls `view.setBounds()` using the reported CSS-pixel rect, converting to physical pixels with `devicePixelRatio`.
- **Show/hide, not create/destroy.** Tab switching toggles `view.setVisible()` — views are reused, not recreated.
- **Corner clipping.** Container uses `overflow: hidden` + `border-radius` so the native view's corners appear rounded. `View.setBorderRadius()` (Electron 33+) also available.

| Property | Transition |
|----------|------------|
| None | Container has no transitions — it's a static frame. Loading feedback lives in the [Address Bar](/components/address-bar). |

---

## Keyboard & Focus

- Content host itself is not focusable — focus passes through to the `WebContentsView`.
- **Ctrl+T** opens a new tab (shows content, hides empty state).
- **Ctrl+W** closes active tab (may reveal empty state).

---

## Accessibility

- Container is a presentational `<div>` — no ARIA role needed.
- Empty state hint text is `select-none` but visible to screen readers.
- `WebContentsView` manages its own accessibility tree.

---

## Layout & Composition

- Lives inside the Shell body flex row, after the [Sidebar](/components/sidebar).
- `flex: 1` with `overflow: hidden` and `position: relative`.
- Margin from `--content-inset` (`0.5rem`) provides breathing room between content and window edge.
- Z-index: `--z-content` (`1`), below chrome (`10`) and overlays (`100`).
