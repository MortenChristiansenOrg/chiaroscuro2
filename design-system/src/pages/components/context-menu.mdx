# Context Menu

Right-click overlay for contextual actions on tabs, folders, and sidebar empty space. Rendered in a native BrowserWindow overlay (above WebContentsViews).

## Anatomy

1. **Overlay window** — frameless, transparent child BrowserWindow
2. **Menu container** — glassmorphism-styled `div` inside the overlay
3. **Menu items** — icon + label rows with hover highlight and staggered entrance animation

## States

### Menu Item States

| State | Background | Text | Icon | Trigger |
|-------|-----------|------|------|---------|
| Default | transparent | `rgba(235,235,245,0.85)` | `rgba(235,235,245,0.5)` | — |
| Hover | `rgba(255,255,255,0.1)` | `rgba(255,255,255,0.95)` | `rgba(235,235,245,0.8)` | pointer hover |
| Active | `rgba(255,255,255,0.16)` | `#fff` | — | mousedown |
| Disabled | transparent | `rgba(235,235,245,0.25)` | opacity `0.3` | `disabled: true` |

Active state also applies `transform: scale(0.98)` for tactile feedback.

Disabled items ignore clicks via `pointer-events: none`.

## Behavior

- **Open:** right-click (`contextmenu` event) on a supported element
- **Close:** click outside (blur), Escape key, parent window move/resize
- **Position:** appears at cursor (renderer `clientX/Y` → main process screen coords), offset for body padding
- **Edge clamping:** repositions if menu overflows parent window bounds (6px margin)
- **Measured before shown:** items rendered via `executeJavaScript`, size measured including body padding, then window positioned and shown
- **No nesting:** only one context menu open at a time

## Animation

### Menu Container
- **Enter:** `menu-in` — `160ms cubic-bezier(0,0,0.2,1)`, scale `0.92 → 1`, translateY `-4px → 0`, opacity `0 → 1`
- **Exit:** window hidden instantly

### Menu Items
- **Enter:** `item-in` — `120ms cubic-bezier(0,0,0.2,1)`, translateX `-4px → 0`, opacity `0 → 1`
- **Stagger:** each item delayed by `30ms × index`
- **Hover transition:** `80ms ease-out` on background and color

---

## Keyboard & Focus

- **Escape:** dismisses menu
- **Blur:** closes the context menu (click anywhere outside)

No keyboard focus — items are mouse-only.

---

## Architecture

The context menu uses a native overlay pattern (same as tooltips) to render above WebContentsViews:

1. Renderer calls `sendCommand("context-menu:show", { items, x, y })`
2. Main process renders items (with icons) in overlay BrowserWindow via `executeJavaScript`
3. Overlay shown, awaits click selection or blur dismiss
4. Command response returns selected index (`-1` for dismiss)
5. Renderer invokes the stored callback at that index

### Font Loading

The overlay HTML is written to a temp file (`app.getPath("temp")`) and loaded via `loadFile()`. This allows the `@font-face` rule to reference the Font Awesome woff2 file via `file://` URL, resolved from `__dirname` at init time.

## API

```tsx
const { open, portal } = useContextMenu();

// In a handler:
const handleContextMenu = (e: React.MouseEvent) => {
  open([
    { label: "Pin tab", icon: "thumbtack", onSelect: () => { ... } },
    { label: "Close tab", icon: "xmark", onSelect: () => { ... } },
  ], e);
};

// In JSX (portal is null, kept for API compat):
<div onContextMenu={handleContextMenu}>...</div>
{portal}
```

### `ContextMenuItem`

| Prop | Type | Description |
|------|------|-------------|
| `label` | `string` | Display text |
| `icon` | `string?` | FA solid icon name (rendered in overlay) |
| `disabled` | `boolean?` | Grayed out, non-interactive |
| `onSelect` | `() => void` | Callback when clicked |
