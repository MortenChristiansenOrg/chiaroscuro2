# Domain Script Editor

## Overview

`src/features/domain-scripts/DomainScriptEditor.tsx` edits a script directly in domain settings, using explicit Save and Cancel actions.

## Anatomy

1. Name.
2. Run mode and path pattern.
3. JavaScript source and clipboard helper explanation.
4. Optional alias and shortcut for manual scripts.
5. Save / Cancel actions and inline save error.

## Variants

New scripts start enabled in manual mode with an example using `await copy(text)`. Existing scripts preserve their saved fields. Automatic mode hides alias and shortcut and clears those manual bindings when saved.

## Behavior

Changing a field never persists immediately. Save submits the full draft and waits for success. Failure keeps the editor open for correction. Cancel discards the draft. Name, path, and source are required; pattern, alias, and shortcut validation errors appear inline. JavaScript errors appear in the card's last-run feedback after execution. The source area resizes vertically.

## Animation & Motion

Button colors transition with `--duration-fast` / `--ease-out`. Reduced motion removes transitions. No overlay or layout animation applies.

## Keyboard & Focus

Opening focuses Name. Tab follows field order; Enter submits from single-line fields. The JavaScript textarea retains normal multiline keyboard behavior. Escape cancels when no save is pending. Closing returns focus to the triggering Add/Edit action. No focus trap applies to this inline form.

## Accessibility

Every field has an explicit label; help text is associated with `aria-describedby`. A named semantic `form` contains a disabled `fieldset` while saving. Save failures use `role=alert`. Buttons and fields meet `--click-target-min` and expose a visible focus outline.

## Layout & Composition

The editor belongs to the [Scripts section](/components/domain-scripts-section). Run/pattern and alias/shortcut use two columns when space permits and stack on narrow screens. The source textarea fills the available width.
