# Permission Prompt

When a website requests a browser permission (geolocation, camera, etc.), a native OS dialog appears asking the user to Allow or Deny. Decisions persist per-domain and are reviewable in the domain settings page.

---

## Native Dialog

The permission prompt uses Electron's `dialog.showMessageBox` to appear above the tab's native WebContentsView. It shows the domain name and human-readable permission label with Deny/Allow buttons. Escape dismisses as Deny.

The dialog is modal to the app window — no interaction with the browser is possible until the user responds.

## Domain Settings — Permissions Section

Stored permission decisions appear in the domain settings page (`app:domain-settings`), alongside the Custom CSS section. Domain decisions can be toggled or revoked. Global choices take priority and appear as read-only rows marked “inherited from global Settings”, even for domains with no saved decisions. The “Manage global permissions in Settings” button opens application Settings.

### Specs

| Property | Token/Value |
|----------|-------------|
| Section heading | `settingsCategoryHeadingStyle` (shared with CSS section) |
| Empty state font size | `--text-sm` |
| Empty state color | `--muted-foreground` |
| Toggle button padding | `px-3 py-1.5` |
| Toggle button radius | `--radius-sm` |
| Toggle allowed bg | `oklch(accent / 0.12)` |
| Toggle allowed border | `oklch(accent / 0.3)` |
| Toggle denied bg | `--background` |
| Toggle denied border | `--input` |
| Revoke button color | `--destructive` |
| Button gap | `0.375rem` |

### States

| State | Toggle | Revoke |
|-------|--------|--------|
| Allowed | Accent bg, `--foreground` text, toggle-on icon | Visible |
| Denied | `--background` bg, `--muted-foreground` text, toggle-off icon | Visible |
| No decisions | — | — (empty state message shown) |

### Button States

| State | Toggle | Revoke |
|-------|--------|--------|
| Default | Per allowed/denied styling above | `--destructive` text+border |
| Hover | `brightness-110` | `brightness-125` |
| Active | `brightness-90` | `brightness-90` |

### Behavior

- **Toggle** sends `permissions:set` command, switching between allow/deny
- **Revoke** sends `permissions:revoke` command, removing the stored decision
- After revoking, the next permission request from that site will show the native dialog again
- Permission list updates in real-time via `permissions:changed` event

### Accessibility

- All buttons have `data-tip` and `aria-label`
- Toggle buttons communicate current state: "Allowed" / "Denied"
- Revoke buttons include permission name in aria-label

### Inherited state

An inherited row displays the effective Allowed/Denied choice and its global source as text. It has no toggle or revoke action. Reset the global choice in [Global Permissions](/components/global-permissions) to restore any saved domain decision.
