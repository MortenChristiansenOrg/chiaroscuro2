# Colors

All colors use `oklch(L C H / alpha)`. No hex, rgb, or hsl. The color system has two contexts: **glass** (browser chrome over the window background) and **content** (opaque panels for web content and settings). There is no dark mode — the glass chrome is always dark (light text on translucent dark), and content panels are always light.

## Glass Context (Chrome UI)

The chrome renders over a semi-transparent background that reveals the OS window acrylic effect, with `backdrop-filter: blur(0.75rem)`. All chrome colors are white or near-white at varying opacities.

## Workspace Accent Colors

Each workspace has a user-chosen accent color exposed as `var(--accent-hue)` — a single hue value. The chrome UI is deliberately achromatic so any accent harmonizes.

| Role | Value | Usage |
|------|-------|-------|
| Accent solid | `oklch(0.65 0.15 var(--accent-hue))` | Focus rings, active indicators |
| Accent muted | `oklch(0.65 0.15 var(--accent-hue) / 0.4)` | Workspace ring, subtle highlights |
| Accent glow | `oklch(0.65 0.15 var(--accent-hue) / 0.8)` | Loading gradient, animated borders |

## Window Background

The window background is semi-transparent with no gradient, allowing the OS acrylic/vibrancy effect to show through:

```css
background: oklch(0.35 0.06 250 / 0.65);
```

## Rules

1. **No new colors without a role.** Every color must map to a role in the tables above. If you need a color that doesn't fit, add the role first.
2. **Opacity over new lightness.** In the glass context, adjust opacity of white rather than introducing new lightness values. This ensures the acrylic effect bleeds through consistently.
3. **3-state text brightness.** Interactive text uses three states: default (`0.55`) → hover (`0.75`) → active (`0.95`). This progression must be consistent across all glass UI text.
4. **Window background is not a design surface.** Never place text directly on the window background. All text must be on a glass or content surface.
5. **Color is accent-only.** The chrome UI is achromatic by default — white text, white/transparent backgrounds, no hue. Color appears only through the accent system or the destructive semantic.
6. **Never hardcode accent hues.** Always derive accent colors from `var(--accent-hue)`.
7. **Accent sparingly.** Use accent for focus rings, active workspace indicators, loading animations, and primary action buttons. Don't use it for backgrounds, text, or borders in normal states.
8. **No dark mode.** Single appearance. Glass chrome is dark by nature. Content panels are always light.
