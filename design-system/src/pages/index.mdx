# Chiaroscuro Design System

Rules and principles for building the Chiaroscuro browser UI. This document is the canonical reference — all UI code must conform to it. When in doubt, follow the rule. When a rule doesn't cover a situation, follow the nearest principle and flag the gap.

## Design Philosophy

Chiaroscuro is a personal browser. Its chrome should disappear — web content is the main character, browser UI is the stage. Every pixel of chrome must justify its existence.

**Core principles:**

1. **Glassmorphism with restraint.** Translucent layers over a semi-transparent background that reveals the OS window acrylic effect, with backdrop blur. The glass creates depth without heaviness. Never stack more than one translucent layer — it muddies readability.
2. **OKLCH everywhere.** All colors in oklch for perceptual uniformity. No hex, rgb, or hsl.
3. **Soft geometry.** Pill shapes for interactive elements (tabs, URL bar), rounded rects for containers. Never sharp corners in the chrome UI.
4. **Quiet until needed.** Default states are subdued. Elements reveal themselves through interaction — hover brightens, focus highlights, active promotes.
5. **Density over sprawl.** Browser chrome should be compact. Prefer smaller text, tighter spacing, and fewer visual elements. Every saved pixel goes to web content.
6. **Command-driven.** Chrome actions are triggered via commands and shortcuts, not Tab navigation. Chrome elements use `tabIndex={-1}` — only overlays and form inputs receive keyboard focus.
